# RTSU

## Запуск проекта на Windows

Инструкции ниже рассчитаны на PowerShell. Команды выполняй из папки проекта, где находятся `README.md` и `docker-compose.yml`.

### 1. Установи программы

Установи Git, Python и Docker Desktop. Запусти Docker Desktop и дождись, пока он полностью запустится. Если на компьютере уже есть PostgreSQL, Docker для базы можно не использовать.

### 2. Скачай проект и установи зависимости

Открой PowerShell и выполни:

```powershell
git clone https://github.com/firdavsjons/RTSU.git
cd RTSU
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

### 3. Настрой подключение к базе

Открой `.env`:

```powershell
notepad .env
```

Для простого локального запуска с Docker оставь имя пользователя и базы из примера, но придумай свой пароль и замени `SECRET_KEY` на случайную строку. Укажи один и тот же пароль в `POSTGRES_PASSWORD` и `DATABASE_URL`; имя базы, пользователь и порт в этих настройках тоже должны совпадать. Для пароля удобнее использовать латинские буквы и цифры, чтобы специальные символы не мешали адресу подключения.

Сгенерировать секретный ключ можно из PowerShell в папке проекта:

```powershell
.\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_hex(32))"
```

Скопируй результат в `.env` после `SECRET_KEY=`.

### 4. Запусти PostgreSQL и создай таблицы

Если порт `5432` свободен, запусти базу в Docker:

```powershell
docker compose up -d db
```

При первом запуске с новым Docker-хранилищем Docker сам создаст базу с именем из `POSTGRES_DB`. Затем создай в ней таблицы приложения:

```powershell
.\.venv\Scripts\python.exe -m alembic upgrade head
```

Если порт `5432` уже занят установленным PostgreSQL, не запускай Docker-базу. Используй существующий сервер и укажи его логин, пароль и имя базы в `DATABASE_URL`. Проверь в pgAdmin, что такая база уже существует; если нет, создай её там или попроси администратора PostgreSQL.

### 5. Создай администратора

Для каждой отдельной базы это делается один раз. В PowerShell выполни:

```powershell
$env:PYTHONPATH = "backend/python"
.\.venv\Scripts\python.exe -m scripts.create_admin admin "придумай-сильный-пароль" "Главный Админ"
Remove-Item Env:PYTHONPATH
```

Если база общая для команды, не создавайте повторно того же администратора. Для общей базы, расположенной на другом компьютере, в `DATABASE_URL` укажи адрес этого компьютера вместо `localhost`. Не отправляй свой `.env` или пароль в GitHub или общий чат.

### 6. Запусти сервер

```powershell
.\.venv\Scripts\python.exe -m uvicorn --app-dir backend/python app.main:app --reload
```

Оставь это окно PowerShell открытым. Открой [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs) для работы с API. Остановить сервер можно сочетанием `Ctrl+C`.

### Что важно знать о базе и настройках

- `POSTGRES_DB` — имя базы. Docker создаёт её автоматически при первом запуске с новым хранилищем данных. Для уже существующего локального PostgreSQL базу нужно создать отдельно, если её ещё нет.
- Если Docker-хранилище уже создавалось раньше, изменение `POSTGRES_USER`, `POSTGRES_PASSWORD` или `POSTGRES_DB` в `.env` не меняет автоматически существующих пользователей и базу.
- `alembic upgrade head` создаёт таблицы приложения. Эту команду выполняют после подготовки базы и повторяют, если в проекте появились новые миграции.
- FastAPI не создаёт базу или таблицы при запуске.
- У каждого разработчика обычно своя локальная база и свой `.env`. Файл `.env` содержит пароли и не отправляется в Git.
- При общей базе укажи в `DATABASE_URL` адрес PostgreSQL, доступный всем участникам; `localhost` подходит только для базы на этом же компьютере. Миграции запускают для общей базы, а учётную запись администратора создают один раз. Не делитесь паролем администратора в репозитории.

## О проекте

Бэкенд университетской системы. Пользователь входит по логину и паролю и видит свой профиль. Ролей три: студент, преподаватель и админ.

**Стек:** Python, FastAPI, PostgreSQL, Alembic (миграции), JWT (токены), argon2 (хеш паролей).

## Как работает авторизация

- Самостоятельной регистрации нет. Первого админа создают вручную скриптом, дальше админ сам создаёт студентов и преподавателей.
- Пользователь отправляет логин и пароль на `POST /auth/login` и получает токен (живёт 30 минут).
- Токен передаётся в заголовке `Authorization: Bearer <токен>`.
- Каждая роль видит только своё. Если роль не подходит, сервер отвечает `403`.

| Код | Значение |
|---|---|
| 401 | нет токена или он неверный/просроченный |
| 403 | токен верный, но роль не подходит |
| 409 | такой логин уже существует |

## Эндпоинты

| Метод и путь | Кто может | Что делает |
|---|---|---|
| `POST /auth/login` | все | вход, выдача токена |
| `GET /users/me` | любая роль | базовые данные и роль |
| `GET /students/me` | студент | ФИО, курс, направление |
| `GET /teachers/me` | преподаватель | ФИО, кафедра, должность |
| `POST /admin/students` | админ | создать студента |
| `POST /admin/teachers` | админ | создать преподавателя |
| `GET /health` | все | проверка, что сервер работает |

Документация и проверка запросов: http://127.0.0.1:8000/docs

В Swagger запросы входа и создания студентов/преподавателей можно отправлять как форму с отдельными полями или как JSON. Для защищённых запросов сначала нажмите **Authorize** и введите полученный токен; отдельные поля логина и пароля администратора при создании пользователя не нужны.

## Структура проекта

```
backend/python/app/
├── domain/          # ядро: сущности, роли, ошибки, интерфейсы репозиториев
├── application/     # сценарии (use cases) и интерфейсы хешера и токенов
├── infrastructure/  # PostgreSQL, argon2, JWT
├── presentation/    # роутеры FastAPI, схемы, зависимости
│   └── api/request_body.py # чтение формы и JSON
├── config.py        # настройки из .env
└── main.py          # точка входа
backend/python/tests/ # тесты
migrations/          # миграции Alembic в корне проекта
scripts/             # служебные скрипты (create_admin.py)
```
## Что лежит в каждом слое

Зависимости идут только внутрь: внешние слои знают о внутренних, но не наоборот. `domain` ничего не знает ни про базу, ни про FastAPI.

### domain/ (ядро: «что такое университет»)

Здесь нет ни SQL, ни FastAPI, только чистый Python.

- **`enums.py`**: список ролей (студент, преподаватель, админ), чтобы не писать строки `"student"` по всему коду.
- **`entities/`**: «объекты предметной области». `User`, `Student`, `Teacher` — простые классы с полями (id, логин, курс, кафедра...). Это то, с чем работает вся логика.
- **`exceptions.py`**: свои ошибки: логин занят, неверный пароль, токен недействителен, студент не найден. Ядро бросает их, а внешний слой решает, какой HTTP-код вернуть.
- **`repositories/`**: интерфейсы репозиториев, то есть «договоры»: список методов («найти по логину», «создать студента») без реализации. Ядро говорит, что ему нужно, но не как это сделать.

### application/ (сценарии: «что система умеет делать»)

- **`use_cases/`**: по одному файлу на действие: войти, создать студента, создать преподавателя, получить профиль студента, получить профиль преподавателя. Внутри вся бизнес-логика: проверить, что логин свободен, сверить пароль, назначить роль. Сценарии работают только с интерфейсами, поэтому не знают, что внизу PostgreSQL.
- **`interfaces/`**: «договоры» для технических сервисов: хешер паролей (хешировать и проверять) и сервис токенов (создать и расшифровать токен). Тут только описание, что умеем, без реализации.

### infrastructure/ (техника: «как именно это работает»)

Здесь живёт всё, что связано с внешним миром.

- **`database/connection.py`**: подключение к PostgreSQL. На каждый запрос открывает соединение и закрывает его, коммитит при успехе и откатывает при ошибке.
- **`repositories/`**: реализации интерфейсов из `domain`: реальный SQL-код. Репозитории пользователей, студентов и преподавателей. Принимают и возвращают сущности домена, а не сырые строки из базы.
- **`security/`**: реализации интерфейсов из `application`: `argon2_hasher.py` хеширует и проверяет пароли, `jwt_service.py` создаёт и проверяет токены.

### presentation/ (вход: «как с системой говорит внешний мир»)

Всё про HTTP и FastAPI.

- **`api/routes/`**: эндпоинты. Каждый роутер тонкий: принял запрос, вызвал сценарий, превратил доменную ошибку в HTTP-код (401, 403, 409). Файлы по темам: вход, пользователи, студенты, преподаватели, админ.
- **`api/schemas/`**: формы данных на входе и выходе API: что клиент присылает (логин, пароль, курс) и что получает обратно. Именно тут гарантируется, что `password_hash` никогда не уходит в ответ.
- **`api/dependencies.py`**: «сборочный цех». Здесь описано, какой репозиторий, хешер и токен-сервис выдать каждому сценарию, а также `get_current_user` (достаёт пользователя из токена) и `require_roles` (проверка роли).

### Остальное

- **`config.py`**: читает `.env` и отдаёт настройки (адрес базы, секретный ключ, срок жизни токена).
- **`main.py`**: точка входа. Создаёт приложение FastAPI и подключает роутеры.
- **`migrations/`**: миграции Alembic, пошаговая история структуры базы. `env.py` настраивает подключение, в `versions/` лежат сами миграции (сейчас создание таблиц `roles`, `users`, `students`, `teachers`).
- **`scripts/`**: служебные инструменты вне приложения. Сейчас там `create_admin.py` для создания первого админа вручную.

### Как это связано на примере входа

1. **presentation**: роутер `/auth/login` принимает логин и пароль.
2. **application**: сценарий входа просит найти пользователя, сверяет пароль и просит выдать токен.
3. **infrastructure**: репозиторий делает SQL-запрос, argon2 сверяет хеш, JWT создаёт токен.
4. **domain**: сущность `User` и ошибка «неверные данные» используются на всём пути.

Зависимости идут только внутрь: ядро ничего не знает про FastAPI и базу.

## Запуск с нуля

Для первого запуска выбери инструкцию выше: **«Запуск проекта на Windows»** или **«Запуск проекта на Mac»**. В ней есть все шаги — от клонирования репозитория до открытия Swagger. После установки проекта сервер можно запускать командой для своей системы из шага 6.

## Как перезапустить

- Сервер запущен с `--reload`, поэтому при сохранении файла он перезапускается сам.
- Остановить: `Ctrl+C` в терминале. Чтобы запустить снова, используй команду из шага 6 для своей системы.
- Если терминал закрыли, открой новый в корне проекта и снова выполни команду запуска.
- Если появились новые миграции после `git pull`, активируй виртуальное окружение либо укажи путь к Python из `.venv`, затем выполни `alembic upgrade head`.

## Быстрая проверка в Postman

1. `POST /auth/login`, Body → raw → JSON: `{"login": "admin", "password": "пароль-администратора"}`. Скопируй `access_token`.
2. `GET /users/me`, Authorization → Bearer Token → вставь токен. Придут данные админа.
3. `POST /admin/students` с токеном админа:
```json
{
  "login": "student1",
  "password": "Student123",
  "full_name": "Иванов Иван",
  "course": 2,
  "direction": "Информатика"
}
```
4. Войди как `student1` и открой `GET /students/me`.
